# Controlled user-unit enforcement proof

This source-only preparation requires root review before push or CI execution. It adds one isolated proof after the successful owned metadata gate; it does not build, fetch dependencies, install software, start a container, touch a preview/native unit or connect to Core.

The controller rechecks the exact current clean Git source, unchanged lock/features, existing tools and observed user-manager1001 context from CI38016306468. It hard-pins the observed absolute systemd-run/systemctl paths and binary hashes. An initial read-only stage resolves existing `/usr/bin/python3`, hashes it, requires direct Python3.12 and captures its version; the exact same executable hash is rechecked before launch. There is no interpreter/tool installation or alternate fallback. Child execution uses `-B -I -S` to suppress bytecode, inherited Python paths and site hooks.

The single unit name contains validated job/run attempt and a fresh random nonce. All copied source/context/receipt/control bytes are new children of the owned RUNNER_TEMP directory. Properties request CPU100%,64MiB,16tasks,15s runtime,5s stop timeout, Nice19, IOWeight1, ProtectSystem strict, readonly root with only the private proof directory writable, PrivateNetwork, PrivateUsers, NoNewPrivileges and control-group termination.

The pure-stdlib child records actual cgroup cpu.max/memory.max/pids.max/io.weight and priority; namespace identity differs from the runner; only loopback and loopback routes exist. It attempts a write only to a newly created, permissive controlled fixture outside its writable directory: EROFS is required, so ordinary DAC denial does not masquerade as a read-only filesystem. No socket or Core connection is attempted. The child retains its unit briefly for the parent to read exact actual unit runtime/protection/resource properties, then exits on a local release marker. The controller waits for actual completion; metadata alone is not acceptance.

Absent permissions, unsupported protections, drift, bad properties, child failure or timeout fails closed. Original unit stdout/stderr and failures remain in the exclusive probe folder. On an uncertain live probe, cleanup can stop only its exact unique probe unit; there is no proof retry, shared setting change, native unit action or privilege fallback. Source tests do not establish actual user namespace/cgroup capability. Full build admission stays false even after this small scope succeeds: larger build resources, dependency checksums/vendor closure, complete Linux/RocksDB/Hyper tests, existing-store/reorg correctness and native source parity still need qualification.

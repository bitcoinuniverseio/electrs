# Larger scope controller: not admitted

`full-cargo-scope.py` prepares a distinct explicit worker, with no default
launch, upload, mount, compiler execution, or workflow activation. Eighteen
pure controls cover aggregate capacity, daemon RLIMIT syntax, path/UID guards,
final-lock mismatch, bounded hash append/open handling, exact tool roles,
setup versus actual wrapper O_EXCL logs, and rejection before unit creation.

The fixed regular 8 GiB image is the aggregate physical filesystem ceiling.
Its inode/device/length are fenced; sparse logical length and allocated blocks
are reported separately. The foreground FUSE daemon gets a hard 8 GiB
RLIMIT_FSIZE, independently read from its actual `/proc/PID/limits`. Cargo
home, home, target, temporary files, aliases and stdout/stderr reside inside
the filesystem. Mount acceptance, mapped dependency hashes, credentials and
cgroup use the reviewed small-proof primitives; rejected unknown mounts are
never unmounted. Only owned child groups are stopped on a deadline.

The larger actual cgroup must show CPU200%, 4 GiB, 128 tasks, IOWeight1 and
Nice19. The parent prepares the exact unique unit and RuntimeMax1800s;
the worker reads actual lifetime/kill/stop properties before mount. Mount setup
requires the previously reviewed SUID helper path; Cargo itself must pass
through the independently compiled expanded Landlock/seccomp wrapper with
NNP and no inherited descriptors/network/io_uring access. This draft does
not claim that expanded wrapper or Cargo compatibility has been proved.

An independently reviewed context hash binds source, final lock, manifests,
wrapper and exact compiler closure. The supplied qualification booleans are
not self-verifying evidence: parent admission loads raw small/wrapper proofs,
rejects missing schemas/controls/compile bindings and verifies complete
immutable source/vendor file sets. It rehashes closed tool leaves and SDK
trees, compares exact read-root bytes, rejects overbroad trees and requires
actual compiler role/alias pins, preserving requested-to-resolved identity.
The explicit larger-scope launch code is
prepared; its Linux behavior and transfer receiver remain unqualified.
The old204 vendor may only accompany its exact old lock. After the pending
upstream merge, acquire/materialize a new complete final-lock vendor closure;
do not relabel old files or substitute dependency versions.

Next source-reviewed transfer recipe: root freezes merged source and its
full Git manifest; root seals the new lock-specific vendor and assigns a new
private draft release with exact asset IDs/hashes. Extend the GET-only driver
with that literal release capsule and bounded receiver, independently verify
all files/checksums, then create a fresh task root. Compile/check the expanded
static confinement wrapper and its behavioral controls first. Only a later
explicit root-reviewed workflow may create the one larger unit. No current
workflow path automatically starts Cargo.

Operator entry point is preparation-only by default. After independent root
review and immutable staging, the explicit parent command is
`full-cargo-scope.py --launch-reviewed-root TASK --reviewed-context-sha256 SHA`.
It checks current Git/source, performs admission, fresh CPU/IO pressure limits
and at least5GiB available RAM/10GiB temporary disk, then invokes the one
pinned user unit. Parent verification writes one exclusive raw-hashed
admission receipt carrying the originally verified input inode/device/size,
mtime/ctime, mode, owner/group and link-count fences. Already-hashed unchanged
files are reused within that one parent operation; changed identities require
a new hash and must still match their original manifests. The worker checks
those fences instead of reading the complete source/vendor/tool trees twice;
changed files or directory metadata fail. It reads actual cgroup limits.
This metadata check is a continuity fence, not a new observation or renewed
source proof. This entry point must not be wired into a default
workflow until root reviews all source and observes prerequisite proofs.

The context schema is `universe-electrs-full-cargo-worker-v1`. Exact raw JSON
bindings include small/wrapper receipts, source/vendor manifests, controller
source, wrapper source/binary, offline config, read-root file and a separate
`universe-electrs-reviewed-compiler-closure-v1` manifest. That reviewed closure
carries its observation receipt SHA, explicit requested/resolved role map,
exact resolved leaf byte hashes and
executable flags, complete SDK/tree file manifests and exact read-root grants.
The expanded wrapper receipt schema is deliberately distinct from the tiny C
proof; it requires compiled/static ELF, exact source/binary and named observed
confinement/Cargo compatibility controls. No existing tiny proof is relabelled.

GCC startup objects, archives and linker-script aliases are still a required
exact-leaf closure. Dynamic ELF/header metadata alone does not establish those
leaves. Root's current read-only probe stays frozen; add a targeted successor
only after actual missing records are reviewed. No whole`/usr/lib` grant is
accepted as a shortcut.

Bindgen/libclang may also require its actual clang resource include tree,
such as an observed LLVM18 resource directory under the system or pinned
local prefix. Neither location is currently proven. A later targeted
manifest-bound observation must identify exact path, file set and hashes
before adding that read-only tree. Whole LLVM library trees and guessed
resource paths are not admitted; the queued ca3 metadata job does not
establish this missing closure.

The wrapper alone creates `cargo.stdout`/`cargo.stderr` with `O_EXCL`;
launcher output uses separate setup files. Mount/log observation failures,
owned unmount and stored daemon settlement are attempted independently.
Unknown mounts are retained. Primary worker failure, parent execution errors
and cleanup failures are reported separately; cleanup does not manufacture
success or discard the original exit. All commands remain unexecuted.

`retained-cargo-cache.py` is a separate admission foundation with five pure
controls. Its dependency key excludes source revision, but binds exact final
lock/vendor bytes and canonical absolute dependency/work paths, resolved
compiler/SDK contents, wrapper bytes, environment and flags. A source-only
type fix can propose reuse under that unchanged key; Cargo's fingerprinting
still decides the affected crates. Raw execution proof hashes and exact
post-settlement image metadata are mandatory, followed by fresh read-only
absence of the known previous unit/cgroup, daemon PID and mount.

This module does not remount or certify a cache from declarations. Root approved
the narrow persistent namespace
`/home/github-runner/.cache/universe-electrs-api-20261009/<16hexnonce>`.
Exclusive creation/lease functions and full-worker namespace validation are
prepared: UID/GID1001,0700, no linked ancestors, checked owned parents,
creating run/source/controller and original root inode in raw-bound lease.
No directory has been created. Remount/reuse wiring remains incomplete;
the current first-run worker refuses existing image/work paths. That remaining
gate must be resolved before source-fix reruns are dispatched. Observed runner
temporary directories may be cleaned at job completion; the approved
persistent root avoids depending on those temporary files. Same canonical
vendor/work paths and original image fences remain required; relocated or
cleaned images fail.
Shared Cargo cache mutation, blind target reuse and recompiling unchanged
RocksDB after every source fix are not acceptable substitutes.

`expanded-cargo-smoke.py` prepares a separate actual minimal Cargo proof.
It compiles the expanded static wrapper from both source files using pinned
existing GCC, records source/binary/readelf hashes, then runs a literal
zero-dependency Cargo crate/build script under the wrapper. Canaries check an
inherited owned FD100, DAC-writable outside file denied by Landlock, private
OUT_DIR writes, IPv4/Unix sockets and io_uring EPERM. Parent checks headroom
before tool/SDK hashes and mkdir; the child uses parent material identity
fences. The distinct proposed unit is CPU100%,512MiB,32tasks,60s/NNP, with
actual cgroup/unit-property checks, output bounds and own-failure logs.
Three pure controls pass; no static wrapper compilation or Cargo execution
has occurred. This is not the old tiny8bec proof or full Electrs qualification.

Frozen draft execution gates: actual small FUSE proof, complete compiler
closure including startup objects/archives/linker scripts, merged final lock
and sealed vendor, independently compiled expanded-wrapper smoke, persistent
lease creation and retained-image wiring, actual larger unit/storage proof,
full Cargo/RocksDB/Hyper tests. The metadata job still uses frozen ca3; these
new draft files are not part of that executed input set. Source and pure-test
results cannot substitute for any of these runtime gates.

Current blockers are actual small FUSE admission (last attempt rejected PSI
before transfer), merged source/final lock, observed compiler/linker/header

admission. Successful `test-compile` is compilation evidence only; successful

# Owned Linux source preflight

This draft workflow resolves metadata and runner access only. It does not qualify the pager or execute Cargo, compilation, dependencies, databases, Core calls or native service actions. Source draft42ef9c89 and its immutable archive remain historical evidence.

`universe-native-preflight.yml` runs only on `codex/bounded-script-utxo-pages` in `bitcoinuniverseio/electrs`. It offers manual dispatch and a push trigger limited to the exact new workflow and its two preflight script paths. It uses the existing `self-hosted, universe-runners-1` fleet, five-minute timeout, contents-read permission and the existing exact pinned checkout action. No host-tools installer action, rustup, default compiler fallback or third-party runner is invoked. Source checkout is the sole planned GitHub source transfer; the preflight itself performs no network request. All inherited compile, tag publication and project mutation jobs are upstream-only so opening a fork draft PR cannot route them to the wrong fleet or installers.

GitHub requires a manual-dispatch workflow to exist on the default branch before registration. The narrowly filtered push trigger lets root register and run this source preflight without changing the fork default branch or adding a default-branch stub. No other path or branch push selects this job. See [GitHub workflow event documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch).

The script inspects the exact existing1.89.0 GNU x86_64 home toolchain directory. Absent tools are recorded, never installed or substituted. It invokes absolute rustc metadata/version only, records cargo presence/hash without invoking Cargo, and records existing C/C++/libclang paths. Tools must resolve outside the checkout. It pins the current clean full Git revision, ancestor draft and unchanged original lock. No cached crate or source is built.

Memory/swap/free temp space and CPU/IO/memory pressure are one metadata observation, not durable headroom. Own unified cgroup controller/limits/write-access and existing unshare/systemd-run binaries plus user namespace limit are metadata only: no cgroup, unit or namespace is created. `sandboxCreationProven` and `durableHeadroomProven` remain false. Successful tool discovery is not full Linux build or adapter qualification. A reviewed later owned resource/network sandbox creation test and locked full Linux build are still required, as are existing-store/reorg completeness and real Hyper/RocksDB integration tests.

Preparation stays local and uncommitted until root review. No push, dispatch or PR is authorized by this document. Missing tools or capabilities must produce precise blockers rather than an installation fallback.

# Historical evidence for bounded reads

The source now connects supplemental edges and historical validation to the existing index writer. Full Linux compilation and checks against real indexes are still pending. This document does not establish native readiness.

The writer verifies canonical block transaction rosters against their Merkle roots, raw transaction IDs, funding outputs, parent confirmations and positions, and corresponding history and supplemental spending rows. Genesis handling keeps its transaction readable while excluding its unspendable coinbase output. Repeated transaction IDs are resolved by canonical funding occurrence, not by the old shared spending key alone.

Each writer window reserves at most 500 logical visits and 1,000,000 work units before dispatch. Dense roster validation and parent confirmation scans resume across windows. Progress and block certificates are written together in a fallible, durable database batch. A marker, count or completed cursor alone cannot publish readiness. After restart, historical evidence is revalidated from genesis. During a reorg, only an already verified canonical prefix may be reused; cumulative work accounting remains intact.

Supplemental edges preserve the script, funding point, spending block hash, height, position, transaction and input in the versioned key. Orphan deletion uses exact keys and retains canonical shared transaction/output records. Storage errors propagate before completion markers advance. Read publication and caches are fenced by the current generation, scope and checked arithmetic. Malformed history, duplicate cached outpoints and missing evidence remain unavailable rather than becoming an empty result.

Old light indexes omit full transaction and roster records. An operator may explicitly provide `--history-proof-dir` pointing to an existing local full txstore, opened read-only. It supplies only missing T/X/M records; primary canonical headers and C/H/O records remain authoritative. Supplied transactions and rosters must match their IDs and the primary canonical Merkle root. The explicit directory is included in the profile commitment; the default profile does not acquire an implicit dependency. No new RPC, import, replay or producer is introduced. Missing evidence remains required work.

The focused checkpoint has 70 reduced-module tests and four extracted cache helper tests passing. Those checks do not compile the full schema adapter. Required next checks cover the final merged dependency versions, Bitcoin and Liquid compilation, actual RocksDB error/atomicity behavior, HTTP connection handling, and real existing-store, restart, reorg and light-index evidence. Native adoption and complete large-address parity require separate receipts.

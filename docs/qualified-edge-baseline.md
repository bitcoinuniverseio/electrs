# Supplemental qualified-edge foundation

The new source module is preparation only. It does not write a namespace, migrate a store, change a producer/reorg/deletion policy, issue RPC, qualify an existing dataset or activate the pager. The provisional fixed146-byte versioned key preserves script/funding point plus spending height, immutable block hash, position, transaction and input. An orphan occurrence of an identical spender therefore cannot share the ancestor key. BIP30 funding incarnations remain separate; old spending height/position cannot spend a newer funding incarnation.

The bounded deletion intent retains up to500 exact original supplemental keys and validates the orphan block before a future fallible atomic backend call. Storage failure propagates, retains the original keys and cannot mark progress complete. No legacy H/S/C/D key is accepted. This primitive does not certify a backend’s atomicity, implement producer retries, fix ignored legacy deletion errors or establish crash recovery. Existing DB deletion semantics remain unchanged until a separately reviewed integration can preserve valid producer behavior and original-key completeness.

Baseline progress retains exact H and nested full-key positions, charges every explicit visit/EOF, bounds500 per operation and1million total, and rejects scope or writer-fence changes. A500-row nested boundary resumes exclusively from the exact last key rather than height/skip. Future insertions below the cursor still require actual same-writer registration and dual-write proof; a Boolean in this foundation is not that proof. EOF/counts/markers can never make readiness true: no historical coverage certificate factory exists, and finishing the scan still returns MissingCoverage.

Existing-store qualification needs independent historical H completeness. The current block store contains X serialized transaction-ID vectors, T raw transactions, C block confirmations and U outputs. Present H rows or done markers cannot prove missing history. A possible source-only audit is bounded decoding of X to a streaming Merkle-root proof against complete headers, then bounded reconstruction/checking of indexed history from canonical transactions and previous outputs. That must handle BIP30/overwrites, source gaps, original deletion failures and all inputs; scanning every canonical block has substantial total work and is not approved or performed. Missing block/transaction/output evidence stays unavailable. No global Core UTXO scan, full-address vector, new RPC pool or native rescan is authorized here.

Before integration: review exact namespace/storage bytes and per-script interest limits; same-writer atomic row/progress registration and below-cursor dual writes; fallible DB batch/error policy without changing legacy exit behavior; canonical/orphan GC that cannot erase ancestor edges; startup/crash qualification and disk/total-work budget; real temporary RocksDB tests and full Linux adapter compilation. Existing-store/reorg coverage and large/default/Main datasets remain required. Focused Windows production-source tests establish these primitives only, not the full migration or native acceptance.

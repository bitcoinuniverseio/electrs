# Small owned fixed-image proof — execution withheld

The actual34d host observation proved the five base host ELF/version leaves,
not the complete mke2fs/mount/helper runtime or a FUSE session. The metadata
successor adds existing host ext2fs/e2p, the pinned setuid fusermount3 ELF and
current kernel release/registered FUSE filesystem names. It opens no device,
runs no helper and explicitly leaves protocol negotiation unobserved.

The pure binder keeps distinct execution groups: fuse2fs uses matched private
ext2fs/FUSE2 and qualified host dependencies; mke2fs and the existing mount
helper use their actual host ext2fs/e2p/base-library closure. Every transitive
NEEDED/loader and every requested version definition is required. Private
replacement versions must not silently satisfy an original host tool's needs.
The input receipts and copied library bytes need independent SHA/path binding;
metadata closure is not execution/storage qualification.

Data-only private extraction is separately default-unexecuted. It verifies all
three original containers before writing, parses no control archive, writes
only bounded regular package payloads, materializes safe library aliases as
identical regular bytes, preserves explicit excluded documentation-link
provenance, and independently reopens all bytes. It changes no host package
database, privilege bits, shared library or trust. Host libraries are not
silently copied/included; they require their own observed-leaf byte checks.

After root reviews actual runtime closure and source, the controller must use
this exact bounded sequence (no automatic retry):

1. Verify reviewed source/receipt hashes, current tool/library byte pins and
   owner UID1001; admit only a new private owned RUNNER_TEMP child. Check fresh
   memory/temp>=1GiB, all CPU PSI averages<=25% and IO<=5%. Snapshot the own
   cgroup/resource context; the old tiny proof does not qualify a new scope.
2. Create an exclusive regular0600 image of exactly8MiB and private mountpoint,
   both under that new child. Bind inode/link count/owner/absolute path. Format
   only this image using the actual pinned existing mke2fs and its complete
   qualified host runtime. Any private formatting config/options require explicit
   source review; no block device, root filesystem or host configuration may be
   selected by arguments.
3. Launch the checksum-bound private fuse2fs in foreground with the exact image
   and mountpoint, explicit nosuid/nodev and no allow_other. Existing setuid mounting is setup capability;
   do not assume it works after NoNewPrivileges or network denial begins.
   Retain its actual Popen PID/start/source identity and bounded own logs.
4. Within a bounded startup deadline observe the exact own mount ID/path/source,
   actual FUSE filesystem and daemon lifetime. Validate a candidate before
   assigning/capturing cleanup ownership; never unmount a rejected unknown mount.
   Validate all four daemon UID/GID values, zero effective/permitted/inheritable/
   ambient capabilities, exact resource cgroup and stable start ticks before/after
   reads, and fresh exact-binding hashes for every staged mapped file.
   A registered kernel module alone
   is not protocol proof. Verify the image remains8MiB and filesystem blocks×
   fragment size do not exceed8MiB. Reject any unexpected mount/helper/owner.
5. Write generated nonfinancial bytes to multiple private files, at most16
   one-MiB operations and16MiB attempted writes total. Force flush/fsync; expect
   real ENOSPC within aggregate filesystem capacity, not merely a per-file
   RLIMIT_FSIZE. Record actual committed byte count, filesystem allocation and
   image size. Include partial file bytes in the8MiB observed-byte bound.
   Reject EIO, deadline, growth, absent ENOSPC or unexpected writes.
6. Reopen/hash all successful file bytes. Record exact capacity and source/image
   identities, retaining any short-write/error result without manufacturing PASS.
7. Unmount only the still-matching own mount ID/path using the existing pinned
   helper. Verify mount absence and actual foreground daemon settlement. On a
   failure preserve the original error plus cleanup errors; only the stored own
   child may be terminated, and only after its ownership identity matches.
   Do not broadly kill a helper, delete artifacts, change permissions/settings,
   or act on any native producer/DB/service.

The executable source controller is now `small-fuse-image-proof.py` with
default-no-action and explicit reviewed receipt-SHA arguments. Its proposed
setup-only unit is CPU100,128MiB,16tasks,30seconds,nice19,IOWeight1, with40s
parent watchdog; actual cgroup cpu/memory/pids/IO/nice and inherited NNP=0 are
checked before staging/image writes. NNP=no is a transient existing-setuid
mounting prerequisite, never a Cargo scope or global security-setting change.
No namespace option or sudo is used. It selects exact copied runtime closures
through a copied loader with inhibited cache and validates daemon file mappings
under the own root. The private ext4 formatting config is source-bounded and
does not modify `/etc/mke2fs.conf`. The controller retains partial writes and
requires actual ENOSPC; its controlled test errno is not kernel proof.

The image and logs stay as evidence; no cleanup scans or repeated launch is
allowed. The controller must have a short outer watchdog plus fail-safe cleanup
of only its own mount/child; inability to settle is a failure with exact remaining
ownership state for root. No source in this preparation opens FUSE or performs
these steps yet. A small successful proof would establish only that tested8MiB
filesystem/lifecycle. Actual8GiB ceiling, larger resource scope, compiler/loader
closure and full Linux compilation still need separate qualification.
